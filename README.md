# Job Application Tracker

A full-stack app for tracking job applications — company, role, status, and notes. Built as a learning project to practice a standard modern web stack end to end: a database, a REST API, and a typed frontend talking to it.

> **Note:** Login is currently disabled for simplicity — the app runs as a single "demo user" so you can use it right away without signing up. The login/signup code is still in the repo, just not wired into the app; see [Re-enabling login](#re-enabling-login) below.

## Tech stack

| Layer     | Choice                                             |
|-----------|-----------------------------------------------------|
| Frontend  | React, TypeScript, Vite, Tailwind CSS, React Router |
| Backend   | Node.js, Express, TypeScript                        |
| Database  | PostgreSQL (hosted on [Neon](https://neon.tech))    |
| ORM       | Prisma                                              |
| Auth      | JWT + bcrypt (built manually, currently disabled)   |

## Running locally

```bash
# from the repo root
npm install                  # root dev tooling (concurrently)
npm install --prefix client
npm install --prefix server

# server/.env
DATABASE_URL="your-postgres-connection-string"
JWT_SECRET="any-long-random-string"
PORT=4000

# client/.env
VITE_API_URL=http://localhost:4000

# push the schema to your database
cd server && npx prisma db push

# from the repo root: runs frontend + backend together
npm run dev
```

- Frontend: http://localhost:5173
- Backend: http://localhost:4000

## File guide

This section explains what every file in the repo is for — useful if you're newer to this stack and wondering "why does this project need a `package.json` *and* a `tsconfig.json` *and* a `vite.config.ts`?"

### Root

| File | What it's for |
|---|---|
| `package.json` | Every Node project's manifest — lists dependencies and defines `npm run <script>` shortcuts. This root one exists only so `npm run dev` can boot **both** `client/` and `server/` together via the `concurrently` package. |
| `package-lock.json` | Auto-generated by npm. Records the *exact* version of every installed package (including sub-dependencies) so everyone who runs `npm install` gets identical versions. Never edit by hand. |
| `.gitignore` | Tells Git which files/folders to never track — `node_modules/` (huge, regenerable), `.env` files (secrets), `dist/` (build output), etc. |
| `neon.ts` | Config for the Neon CLI — declares branch policies for the Postgres database (e.g. auto-expiring temporary branches). Not used by the app itself at runtime. |

### `server/` (the Express API)

| File | What it's for |
|---|---|
| `package.json` | Lists backend dependencies (Express, Prisma, bcrypt, jsonwebtoken...) and scripts: `npm run dev` (start with auto-reload), `build` (compile TypeScript to JS), `start` (run the compiled build), `db:push` (sync the Prisma schema to the database). |
| `tsconfig.json` | Configures the TypeScript compiler for this folder — e.g. "target modern JavaScript," "be strict about types," "output compiled files to `dist/`." |
| `prisma.config.ts` | Tells the Prisma CLI which database to connect to (reads `DATABASE_URL` from `.env`). Required by Prisma 7+; in older Prisma versions this lived directly in the schema file. |
| `.env` *(not committed)* | Secrets and per-environment config: the database connection string, the JWT signing secret, the port to run on. Every developer/deployment creates their own. |
| `prisma/schema.prisma` | The database schema, in Prisma's own syntax — defines the `User` and `Application` tables, their columns, and the relationship between them. Running `prisma db push` reads this file and updates the real database to match. |
| `src/index.ts` | The entry point. Creates the Express app, applies middleware (CORS, JSON body parsing), mounts the route files below, and starts the server listening on a port. |
| `src/lib/prisma.ts` | Creates one shared Prisma Client instance (the object you call `.findMany()`, `.create()`, etc. on) so every file in the app reuses the same database connection instead of opening a new one each time. |
| `src/lib/demoUser.ts` | *Temporary, while login is disabled.* Creates/reuses one fixed "demo" user in the database so every request has something to attach applications to, without requiring a real login. |
| `src/middleware/auth.ts` | Express middleware — code that runs *before* a route handler. Contains `requireAuth` (checks a JWT, rejects the request if invalid — currently unused) and `useDemoUser` (currently active — just stamps every request as the demo user). |
| `src/routes/auth.ts` | Defines `POST /api/auth/signup` and `POST /api/auth/login`. Hashes/checks passwords with bcrypt and issues JWTs. Not currently reachable from the frontend, but fully functional if you call it directly (e.g. with `curl` or Postman). |
| `src/routes/applications.ts` | Defines the CRUD endpoints for job applications: list, create, update, delete. Each one checks that the application belongs to the current user before allowing changes. |
| `src/types/express.d.ts` | A TypeScript-only file — adds a `userId` field to Express's built-in `Request` type, so `req.userId` doesn't cause a type error in the routes above. |

### `client/` (the React frontend)

| File | What it's for |
|---|---|
| `package.json` | Lists frontend dependencies (React, React Router, Tailwind...) and scripts: `dev` (start Vite's dev server), `build` (produce an optimized production bundle), `preview` (serve that production build locally to test it). |
| `tsconfig.json` / `tsconfig.app.json` / `tsconfig.node.json` | TypeScript compiler settings, split into three files by Vite's template: one for app code (runs in the browser), one for config files like `vite.config.ts` (runs in Node), and a root file that just points to the other two. |
| `vite.config.ts` | Configures Vite, the build tool — registers the React plugin (JSX support, fast refresh) and the Tailwind plugin. |
| `index.html` | The single real HTML page of the app. Vite injects the bundled JavaScript into it; React then takes over rendering everything inside `<div id="root">`. |
| `.oxlintrc.json` | Config for `oxlint`, a fast linter that flags common JS/TS mistakes (unused variables, etc.) when you run `npm run lint`. |
| `.env` *(not committed)* | Frontend config — currently just `VITE_API_URL`, the address of the backend API. (Vite only exposes env vars prefixed with `VITE_` to the browser, as a safety measure.) |
| `src/main.tsx` | The actual entry point — finds `<div id="root">` in `index.html` and tells React to render `<App />` into it. |
| `src/App.tsx` | Defines the app's routes (which URL shows which page) using React Router: `/login`, `/signup`, `/dashboard`. |
| `src/index.css` | Global stylesheet — just one line importing Tailwind, which then generates all the utility classes (`bg-slate-50`, `rounded`, etc.) used throughout the components. |
| `src/lib/api.ts` | The only file that calls `fetch()` to talk to the backend. Every other file calls functions from here (`api.getApplications()`, `api.login()`, ...) instead of writing raw fetch calls everywhere. |
| `src/context/AuthContext.tsx` | React Context — a way to share the logged-in user's info across the whole app without passing it down through every component manually. Stores the JWT and user in `localStorage` so a page refresh doesn't log you out. |
| `src/components/ProtectedRoute.tsx` | A wrapper component that redirects to `/login` if there's no logged-in user. Currently unused (login is disabled) but ready to drop back into `App.tsx`. |
| `src/components/ApplicationForm.tsx` | The modal form used for both creating a new application and editing an existing one — same fields either way, just pre-filled when editing. |
| `src/pages/Login.tsx` | The login page/form. Not currently linked to from anywhere in the UI, but reachable directly at `/login`. |
| `src/pages/Signup.tsx` | The signup page/form. Same status as Login — functional, just not linked to right now. |
| `src/pages/Dashboard.tsx` | The main screen: fetches the application list, renders it as a table, and hosts the "Add Application" button and the edit/delete actions. |

## Re-enabling login

The auth system is fully built, just disconnected. To turn it back on:

1. In `server/src/routes/applications.ts`, change `useDemoUser` back to `requireAuth`.
2. In `client/src/App.tsx`, wrap the `/dashboard` route in `<ProtectedRoute>` again (see `src/components/ProtectedRoute.tsx`).
3. Add a way to reach `/login` and `/signup` from the UI (e.g. a link, or redirect unauthenticated users there instead of to `/dashboard`).

## What I'd improve with more time

- Drag-and-drop Kanban board instead of a plain table
- Pagination/search once the list grows
- Swap the hand-rolled JWT auth for a managed provider (e.g. Auth0/Clerk) — kept it manual here deliberately, to understand how token-based auth works
- Deploy live (Vercel for the client, Render/Railway for the API)
